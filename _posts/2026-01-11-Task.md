### 1. Task란

Task는 Swift Concurrency에서 비동기 작업의 실행 단위입니다.

```swift
Task {
    await doSomethingAsync()
}
```

이 한 줄은 다음 의미를 갖습니다.

- 새로운 비동기 작업(Task)을 생성

- 현재 실행 흐름과 독립적으로 실행

- 내부에서 async/await을 자유롭게 사용 가능

즉, Task는 **"지금 흐름과 분리된 비동기 작업을 실행하기 위한 컨테이너"** 입니다.

-----

### 2. Task는 스레드일까?

결론부터 말하면 아닙니다! (Task ≠ Thread)

- Task는 논리적인 작업 단위

- 실제 실행은 Swift Concurrency Runtime이 스레드 풀에서 스케줄링

하나의 Task는 실행 중 여러 스레드를 오갈 수 있고, 여러 Task가 하나의 스레드에서 번갈아 실행될 수도 있습니다.

중요한 점은 **Task는 '어디에서 실행될지'를 보장하지 않는다** 는 점입니다.

-----

### 3. Task의 실행 시점과 특징

#### Task는 생성 즉시 실행됩니다.

```swift
Task {
    print("Task")
}
print("Main")
```

출력 순서는 보장되지 않습니다.

```
Main
Task

또는

Task
Main
```

Task 블록은 생성과 동시에 런타임의 스케줄링 대상이 되며, 호출한 함수의 실행 흐름을 막지 않습니다.

#### Fire-and-forget 작업

```swift
Task {
    await sendLog()
}
```

이런 형태의 Task는 결과를 기다리지 않고 실패 여부에도 관심이 없습니다.

-----

### 4. await을 만났을 때 Task는 어떻게 동작할까?

```swift
Task {
    print("A")
    await fetchData()
    print("B")
}
```

await은 다음을 의미합니다.

- 현재 Task를 일시 중단(suspend)

- 스레드를 점유하지 않고 양보

- 작업이 끝나면 다시 재개(resume)

중요한 점은 await이 스레드 블로킹이 아니라는 점입니다.

>Task는 await 지점에서 멈출 수 있으며, 그 사이 다른 Task들이 실행될 수 있습니다.

-----

### 5. Task와 Actor의 관계

Actor는 내부 상태를 보호하기 위해 한 번에 하나의 작업만 실행합니다.

하지만 await을 만나는 순간, 실행 중이던 작업은 중단될 수 있습니다.

#### Actor 내부에서 Task 생성 시 주의점

```swift
actor UserStore {
    func refresh() {
        Task {
            await fetchUser()
        }
    }
}
```

이 경우:

- 생성된 Task는 actor에 자동으로 묶이지 않습니다.

- actor의 직렬성 보장이 깨질 수 있습니다.

따라서 actor 내부에서는 불필요한 Task 블록 생성을 피하고, 가능한 한 async 함수 형태로 구조화하는 것이 안전합니다.

```swift
actor UserStore {
    func refresh() async {
        await fetchUser()
    }
}
```

### 6. Task와 @MainActor

Task를 사용한다고 해서 메인 스레드에서 실행되는 것은 아닙니다.

```swift
Task {
    view.alpha = 0.5    // ⚠️ 경고 발생 가능
}
```

UI 업데이트는 반드시 `@MainActor`에서 이루어져야 합니다.

**올바른 사용 예**

```swift
Task { @MainActor in 
    view.alpha = 0.5
}
```

또는

```swift
@MainActor
func updateUI() {
    view.alpha = 0.5
}

Task {
    await updateUI()
}
```

>Task는 실행 컨텍스트를 바꾸지 않습니다. Actor 격리는 명시적으로 선언해야 합니다.

-----

### 7. Task 취소(Cancellation)

Task는 취소 가능한 작업입니다.

```swift
let tast = Task {
    await loadData()
}

task.cancel()
```

하지만 취소는 즉시 중단이 아닙니다.

- 취소는 "요청"일 뿐

- Task 내부에서 직접 확인해야 합니다.

```swift
Task {
    guard !Task.isCancelled else { return }
    await loadData()
}
```

또는

```swift
try Task.checkCancellation()
```

이 방식을 **Cooperative Cancellation** 이라고 합니다.

### 8. DispatchQueue와 Task의 차이

| 항목 | Task | DispatchQueue |
| :-- | :-- | :-- |
| 개념 | 비동기 작업 단위 | 스레드 큐 |
| async/await | 지원 | 미지원 |
| 취소 | 가능 | 불가능 |
| Actor 연계 | 자연스럽게 가능 | 불가능 |
| 스레드 관리 | 런타임 자동 | 개발자 간접 제어 |

Swift Concurrency 환경에서 Task가 기본 선택지이며, DispatchQueue는 점진적으로 역할이 줄어들고 있습니다.

-----

### 9. 마무리

Task는 단순히 비동기 함수를 실행하는 문법이 아닙니다.

Swift Concurrency에서 실행, 중단, 재개, 취소를 모두 담당하는 핵심 개념입니다.

Task의 동작 방식을 이해하면

- actor의 직렬성

- @MainActor의 의미

- Swift 6의 Strict Concurrency 경고

까지 자연스럽게 이어서 이해할 수 있습니다.
