## Tuist (Code Sharing + Synthesized files)

지난 번에 이어서 Tuist를 확인해봅니다.

### Code Sharihg - 코드 공유

Xcode를 대규모 프로젝트에 사용할 때 불편한 점 중 하나는 .xcconfig 파일을 통한 빌드 설정 외에는 프로젝트 요소를 재사용하기 어렵다는 점입니다.
하지만 프로젝트 정의를 재사용할 수 있다면 다음과 같은 장점이 있습니다.

- **유지보수 용이성 증가**
변경을 한 곳에서만 적용해도 전체 프로젝트에 전파됩니다.

- **프로젝트 표준화 가능**
새로운 프로젝트가 따를 수 있는 공통 규칙을 정의할 수 있습니다.

- **일관성 향상 -> 깨지는 빌드 감소**
프로젝트 간 구조가 통일되므로 설정 불일치로 인한 빌드 깨짐이 줄어듭니다.

- **새 프로젝트 생성 간편화**
기존 정의를 재사용해 프로젝트 생성이 훨씬 쉬워집니다.

Tuist는 이러한 문제를 해결하기 위해 **Project Description Helpers** 라는 개념을 제공합니다. 이를 통해 여러 manifest 파일에서 코드 재사용이 가능해집니다.

#### Project Description Helpers

Project Description Helpers는 Swift 파일로 이루어져 있으며, ProjectDescriptionHelpers 라는 모듈로 컴파일됩니다.
이 모듈은 Tuist/ProjectDescriptionHelpers 디렉토리 내 모든 파일로 구성됩니다.

manifest 파일에서 아래처럼 import 해서 사용할 수 있습니다.

```swift
// Project.swift
import ProjectDescription
import ProjectDescriptionHelpers
```

**ProjectDescriptionHelpers를 사용할 수 있는 manifest 종류**

- Project.swift
- Package.swift(단 #if TUIST 컴파일 플래그 필요)
- Workspace.swift

#### 예시: Project 모델 확장 + 템플릿 방식 재사용

아래 예시는 Project 모델에 커스텀 static 생성자(featureFramework)를 추가하고 이를 Project.swift에서 사용하는 방법을 보여줍니다.

**Tuist/Project+Template.swift**
```swift
import ProjectDescription

extension Project {
    public static func featureFramework(
        name: String, 
        dependencies: [TargetDependency] = []
    ) -> Project {
        return Project(
            name: name,
            targets: [
                .target(
                    name: name,
                    destinations: .iOS,
                    product: .framework,
                    bundleId: "dev.tuist.\(name)",
                    infoPlist: "\(name).plist",
                    sources: ["Sources/\(name)/**"],
                    resources: ["Resources/\(name)/**"],
                    dependencies: dependencies
                ),
                .target(
                    name: "\(name)Tests",
                    destination: .iOS,
                    product: .unitTests,
                    bundleId: "dev.tuist.\(name)Tests",
                    infoPlist: "\(name)Tests.plist",
                    sources: ["Sources/\(name)Tests/**"],
                    resources: ["Resources/\(name)Tests/**"],
                    dependencies: dependencies
                )
            ]
        )
    }
}
```

#### 요약

- 코드 재사용 : 공통적인 프로젝트 생성 로직을 Swift 코드로 재사용
- 조직 표준화 : 플랫폼 팀이 사내 규칙(네이밍, 구조)을 코드화하여 일관된 프로젝트 구조 제공
- 유지보수 용이성 : 설정 변경 시 모든 프로젝트가 자동으로 업데이트
- DSL 수준 : Swift 문법을 그대로 활용하므로 YAML/JSON 대비 더 강력하고 안전

### Synthesized files

Tuist는 Xcode 프로젝트를 생성할 때, 개발자의 편의성을 높이기 위해 파일 및 코드를 자동 생성(synthesize) 할 수 있습니다.

#### Target resources

Xcode 프로젝트는 타겟에 리소스를 추가하는 기능을 제공합니다.
하지만, 특히 모듈화된 프로젝트에서는 여러 문제가 발생할 수 있습니다.

##### ❗ 1. 일관되지 않은 런타임 접근 방식

리소스가 최종 산출물(앱, 프레임워크 등) 내 어디에 위치하는지는 타겟의 product type에 따라 달라집니다.

예를 들어:
- 앱(App) 타겟 -> 리소스가 앱 번들 안에 복사됨
- 프레임워크 -> 프레임워크 번들 안으로 복사됨

이렇게 위치가 달라지면, 리소스를 접근하는 코드도 번들의 구조를 가정하게 되고, 이는 코드 이동 및 유지보수에 좋지 않습니다.

##### ❗ 2. 리소스를 지원하지 않는 Product 타입들

일부 product 타입(예: static library)은 번들이 아니기 때문에 리소스를 가질 수 없습니다.

따라서 개발자는 다음과 같은 우회 전략을 사용해야 했습니다.
- static library -> 대신 static framework 사용 + 별도의 리소스 copy build phase 필요
- dynamic framework -> 가능하지만 앱 시작 속도 저하 발생

##### ❗ 3. 런타임 오류 발생 가능성

리소스는 문자열 기반(name, extension)으로 접근합니다.

예:

```swift
UIImage(named: "main_icon")
```

이 문자열에 오타가 있으면 컴파일 타임에 잡히지 않고 런타임에서 crash가 발생합니다.

##### ✅ Tuist의 해결 방식

Tuist는 위 문제들을 해결하기 위해:
- 리소스 번들 접근자(Bundle Accessor)
- 리소스 파일 접근자(Resource Accessor)
를 자동 생성해줍니다.

즉, 번들 구조나 product 타입에 상관없이 일관된 방식으로 리소스를 접근할 수 있도록 추상화해 줍니다.

#### Resources(Info.plist, entitlements 등)

Tuist는 Info.plist 또는 Entitlements 파일의 내용을 Swift 코드로 선언할 수 있는 인터페이스를 제공합니다.

**이 방식의 장점**:
- 코드 기반으로 관리 -> 오타나 구조 오류를 컴파일 타임에 잡을 수 있음
- 여러 프로젝트 간 재사용 가능 -> 설정 일관성 유지

이렇게 정의된 파일은 프로젝트 생성 시 Derived/ 디렉토리에 자동으로 생성됩니다.

**📌 Tip — Derived 디렉토리는 Git에 포함시키지 마세요**

.gitignore에 다음을 추가하시는 것을 권장드립니다.

```bash
Derived
```

#### Bundle Accessor(번들 접근자)

Tuist는 타겟 리소스를 포함하고 있는 번들을 쉽게 접근할 수 있는 코드를 자동 생성합니다.

```swift
let bundle = Bundle.module
```

```Objective-C
NSBundle *bundle = [MyFeatureResources bundle];
```

#### Resource Accessors(SwiftGen 활용)

리소스는 문자열로 접근하는 방식이 일반적이지만, 이는 위험합니다.
오타가 나면 컴파일러가 잡아주지 못하고 런타임 crash로 이어지기 때문입니다.

이를 방지하기 위해 Tuist는 SwiftGen을 내부적으로 사용해 리소스 접근 코드를 자동 생성합니다.

기본적으로 생성되는 파일 예시는 다음과 같습니다.
- Images, Colors -> Assets+{Target}.swift
- Strings -> Strings+{Target}.swift
- Plists -> {PlistName}.swift
- Fonts -> Fonts+{Target}.swift
- Files -> Files+{Target}.swift

**❌ 자동 생성 비활성화 옵션도 있음**

프로젝트 단위에서 다음 옵션을 설정하여 비활성화 할 수 있습니다.

```swift
Project(
    options: .options(disableSynthesizedResourceAccessors: true)
)
```
