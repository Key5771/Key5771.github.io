## Tuist (Dynamic Configuration + Templates)

지난 번에 이어서 Tuist를 확인해봅니다.

### Dynamic Configuration - 동적 구성

프로젝트를 생성할 때 환경에 따라 설정을 달리해야 하는 경우가 있습니다.

예를 들어:
- 앱 이름을 환경에 따라 다르게 쓰고 싶거나
- 번들 아이디(Bundle Identifier)를 QA/Dev/Prod 환경에 따라 바꾸고 싶거나
- 배포 타겟(deployment target) 값을 Build 환경 별로 다르게 지정하고 싶은 경우

이럴 때 Tuist는 환경 변수(Environment Variables)를 통해 동적 구성을 지원합니다.

즉, tuist generate 명령을 실행하는 시점에 환경 변수를 전달하면, Manifest 파일(Project.swift 등) 내부에서 해당 값을 읽어 프로젝트 설정을 바꿀 수 있습니다.

#### 환경 변수를 통한 구성(Configuration through Environment variables)

Tuist는 다음과 같이 tuist generate 앞에 환경 변수를 전달할 수 있습니다:

```bash
TUIST_APP_NAME=MyApp tuist generate
```

여러 환경 변수를 동시에 넘기고 싶다면 스페이스로 구분합니다:

```bash
TUIST_APP_NAME=MyApp TUIST_APP_LOCALE=pl tuist generate
```

이 때, 환경 변수 이름은 반드시 아래 규칙을 따라야 합니다:

```bash
TUIST_XXX
```

이 규칙을 따르면 Tuist가 자동으로 인식합니다.

#### Manifest에서 환경 변수 읽기

Manifest 내부(Project.swift 등)에서는 Environment 타입을 통해 변수에 접근할 수 있습니다.

예시로, TUIST_APP_NAME 값을 읽어오는 함수는 다음과 같습니다:

```swift
func appName() -> String {
    if case let .string(environmentAppName) = Environment.appName {
        return environmentAppName
    } else {
        return "MyApp"
    }
}
```

#### Environment의 반환 타입

`Environment.xxx` 로 값을 읽으면 반환 타입은 Environment.Value? 입니다.

| Case | 설명 |
| :-- | :-- |
| .string(String) | 문자열로 전달된 값 |

#### 더 편한 방법 - getString(), getBoolean()

Tuist는 문자열(String)과 불리언(Boolean)을 더 쉽게 읽을 수 있도록 helper 메소드를 제공합니다.

예:

```swift
let name = Environment.appName.getString(default: "TuistServer")
```

Boolean 값도 동일하게 사용할 수 있습니다.

### Templates - 템플릿 기능(Tuist Scaffold)

대부분의 프로젝트는 아키텍처가 어느 정도 정착되면, 새로운 기능이나 컴포넌트를 추가할 때 일관된 구조를 유지하고 싶어집니다.
Tuist는 이를 위해 tuist scaffold 명령을 통해 템플릿 기반으로 파일을 자동 생성할 수 있도록 지원합니다.

템플릿은 Tuist에서 기본 제공하는 템플릿을 사용할 수도 있고, 직접 원하는 구조로 만들 수도 있습니다.

다음과 같은 상황에서 매우 유용합니다.

- 프로젝트 아키텍처에 맞는 새 기능(예: VIPER 등)을 빠르게 생성할 때

```bash
tuist scaffold viper --name MyFeature
```

- 새로운 프로젝트 구조를 생성할 때

```bash
tuist scaffold feature-project --name Home
```

참고사항
> Tuist는 템플릿 파일의 구조나 스타일에 대해 어떠한 의견도 강요하지 않습니다.
단지, 템플릿이 특정 디렉토리 구조 안에 위차하면 된다는 점만 요구합니다.
>

#### 템플릿 정의하기

1. 템플릿 디렉토리 생성

다음 명령을 실행해 Tuist 편집 모드를 여세요:

```bash
tuist edit
```

프로젝트 루트의 Tuist/Templates 디렉토리 아래에 원하는 템플릿 이름으로 디렉토리를 생성합니다.

```
Tuist/
 └── Templates/
      └── name_of_template/
           └── name_of_template.swift  ← 템플릿 manifest
```

예를 들어 framework라는 템플릿을 만들고 싶다면:

```
Tuist/Templates/framework/framework.swift
```

#### 템플릿 manifest 예시

```swift
import ProjectDescription

let nameAttribute: Template.Attribute = .required("name")

let template = Template(
    description: "Custom template",
    attributes: [
        nameAttribute,
        .optional("platform", default: "ios"),
    ],
    items: [
        .string(
            path: "Project.swift",
            contents: "My template contents of name \(nameAttribute)"
        ),
        .file(
            path: "generated/Up.swift",
            templatePath: "generate.stencil"
        ),
        .directory(
            path: "destinationFolder",
            sourcePath: "sourceFolder"
        ),
    ]
)
```

- 템플릿 구성 요소 설명

    - .string : 파일을 문자열로 생성
    - .file : Stencil 템플릿을 이용해 파일 생성
    - .directory : 특정 디렉토리를 복사해서 생성

#### 템플릿 사용하기

템플릿을 정의했다면 아래처럼 scaffold 명령으로 사용할 수 있습니다:

```bash
tuist scaffold name_of_template --name Name --platform macos
```

platform은 optional 속성이므로 다음처럼 생략도 가능합니다:

```bash
tuist scaffold name_of_template --name Name
```

#### Stencil 템플릿 활용

만약 .stirng 또는 .file만으로 충분하지 않다면,
Tuist는 Stencil 템플릿 언어를 지원하기 때문에 더 복잡한 구조도 만들 수 있습니다.

예:
\(nameAttribute)를 사용하면 name 값이 그대로 들어오며,
Stencil 문법을 쓰면 다음처럼 변형도 가능합니다:

```
{{ name | lowercase }}
```

### 전체 디렉토리 복사하기

.directory 옵션을 사용하면 템플릿 안의 폴더 전체를 지정된 위치로 그대로 복사할 수 있습니다.

```swift
.directory(
    path: "destinationFolder",
    sourcePath: "sourceFolder"
)
```

참고사항
>템플릿에서도 ProjectDescriptionHelpers 모듈을 사용할 수 있기 때문에,
여러 템플릿에서 공통으로 사용하는 코드를 손쉽게 재사용할 수 있습니다.
