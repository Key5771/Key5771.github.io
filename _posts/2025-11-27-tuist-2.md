## Tuist (Editing + Dependencies)

지난 번에 이어서 Tuist를 확인해봅니다.

### Editing

기존 Xcode 프로젝트나 Swift Package와 달리 Tuist에서 관리하는 프로젝트는 Manifest 파일에 포함된 Swift 코드로 정의됩니다.
Swift Package와 Package.swift 파일에 익숙하다면 접근 방식이 매우 유사합니다.

이러한 파일은 모든 텍스트 편집기를 통해 수정할 수 있지만, Tuist에서 제공하는 tuist edit 워크플로우를 사용하는 것이 좋습니다.
이 워크플로우는 모든 Manifest 파일을 포함하는 Xcode 프로젝트를 생성하고 이를 편집하고 컴파일 할 수 있도록 합니다. 

#### Edit the project

프로젝트를 편집하려면 Tuist 프로젝트 디렉토리나 하위 디렉토리에서 다음 명령어를 입력합니다.

```bash
tuist edit
```

이 명령어는 전역 디렉토리에 Xcode 프로젝트를 생성하고 Xcode에서 엽니다.
이 프로젝트에는 모든 Manifest의 유효성을 확인하기 위해 빌드할 수 있는 Manifest 디렉토리가 포함되어 있습니다.

#### Ignoring manifest files

프로젝트에 Manifest 파일과 이름이 같은 Swift 파일(예: Project.swift)이 있고, 이 파일이 실제 Tuist Manifest가 아닌 하위 디렉토리에 있는 경우, 프로젝트 루트에 .tuistignore 파일을 생성하여 편집 프로젝트에서 제외할 수 있습니다.

.tuistignore 파일은 glob 패턴을 사용하여 무시할 파일을 지정합니다.

```bash
# Ignore all Project.swift files in the Sources directory
Sources/**/Project.swift

# Ignore specific subdirectories
Tests/Fixtures/**/Workspace.swift
```

이 기능은 Tuist Manifest 파일과 동일한 명명 규칙을 사용하는 test fixture나 예제 코드가 있는 경우에 특히 유용합니다.

#### Edit and generate workflow

생성된 Xcode 프로젝트에서는 편집이 불가능합니다. 이는 생성된 프로젝트가 Tuist에 종속되는 것을 방지하기 위한 의도적인 조치이며, 향후 Tuist에서 손쉽게 이동할 수 있도록 하기 위함입니다.

프로젝트를 반복할 때는 터미널 세션에서 `tuist edit`을 실행하여 Xcode 프로젝트에서 프로젝트를 편집하고, 다른 터미널 세션에서 tuist generate를 실행하는 것이 좋습니다.

-----

### Dependencies

프로젝트가 커지면 코드를 공유하고, 경계를 정의하고, 빌드 시간을 단축하기 위해 여러 대상으로 분할하는 것이 일반적입니다.
여러 대상을 사용하면 대상 간의 종속성을 정의하여 종속성 그래프를 형성하게 되는데, 여기에는 외부 종속성도 포함될 수 있습니다.

#### XcodeProj-codified graphs

Xcode와 Xcodeproj의 설계 특성상 종속성 그래프를 유지하는 것은 지루하고 오류가 발생하기 쉬운 작업이 될 수 있습니다.
발생할 수 있는 몇 가지 문제는 다음과 같습니다.

- Xcode의 빌드 시스템은 프로젝트의 모든 제품을 derived data에서 동일한 디렉토리에 출력하기 때문에, 타겟에서 import 해서는 안 되는 product를 가져올 수 있습니다. CI 환경에서나 나중에 다른 구성을 사용할 경우 컴파일이 실패할 수 있습니다.

- 타겟의 전이적 동적 종속성(transitive dynamic dependencies of a target)은 LD_RUNPATH_SEARCH_PATHS 빌드 설정에 포함된 모든 디렉토리를 복사해야 합니다. 그렇지 않으면 타겟이 런타임에 해당 종속성을 찾을 수 없습니다. 그래프가 작을 때는 쉽게 생각하고 설정할 수 있지만, 그래프가 커질수록 문제가 됩니다.

- target이 정적 XCFramework를 연결할 때, Xcode가 bundle을 처리하고 현재 플랫폼 및 아키텍처에 맞는 바이너리를 추출하기 위해 타겟에 추가 빌드 단계가 필요합니다. 이 빌드 단계는 자동으로 추가되지 않으므로 추가하는 것을 잊기 쉽습니다.

#### Local Dependencies

같은 프로젝트 내부, 또는 다른 프로젝트, 또는 바이너리 형태의 프레임워크/라이브러리 등에 의존성을 걸 수 있습니다.

Target 생성 시 dependencies 파라미터에 다음 옵션을 줄 수 있습니다.

| 종류 | 설명 |
| :-- | :-- |
| .target(name:) | 같은 프로젝트 내 다른 타겟 |
| .project(target: path:) | 다른 Tuist 프로젝트 안의 타겟 |
| .framework(path:) | 바이너리 프레임워크 |
| .library(path:) | 정적/동적 라이브러리 |
| .xcframework(path:) | XCFramework |
| .sdk(name: type:) | 시스템 SDK |
| .xctest | XCTest |
| .external(name:) | 외부 패키지(SPM) |

또한 각 의존성은 condition 옵션을 통해 "플랫폼별 조건부 의존성" 지정이 가능합니다. 기본값은 해당 타겟이 지원하는 모든 플랫폼에 대해 링크됩니다.

**Local 타겟 간 의존성 예시**

```swift
import ProjectDescription

let project = Project(
    name: "Example",
    targets: [
        .target(
            name: "App",
            platform: .iOS,
            product: .app,
            bundleId: "io.tuist.app",
            infoPlist: .default,
            sources: "Sources/App/**",
            dependencies: [
                .target(name: "Core"),
                .project(target: "FeatureA", path: "../FeatureA")
            ]
        ),
        .target(
            name: "Core",
            platform: .iOS,
            product: .framework,
            bundleId: "io.tuist.core",
            infoPlist: .default,
            sources: "Sources/Core/**"
        )
    ]
)
```

#### External Dependencies - 주로 SPM 사용

Tuist는 외부 라이브러리 관리를 위해 주로 Swift Package Manager(SPM)을 추천합니다. SPM 의존성을 사용하는 방식은 다음과 같습니다.

1. 프로젝트 루트나 Tuist/ 디렉토리에 Package.swift 파일을 생성하고, 외부 패키지를 선언

2. `tuist install` 명령어로 패키지 의존성을 해석하고 Tuist/Dependencies 디렉토리로 가져옴

3. 각 타겟에서 .external(name: "패키지이름") 형태로 선언하여 해당 패키지를 의존성으로 설정

또한 Tuist가 만든 프로젝트에서는 SPM 패키지에 대해 자동으로 스킴(scheme)을 생성해주지 않습니다. 스킴이 필요하다면 Xcode에서 수동으로 생성해야 합니다.

**Package.swift 예시**

```swift
// Tuist/Dependencies/Package.swift
// 외부 패키지 선언
import PackageDescription

let package = Package(
    name: "Dependencies",
    dependencies: [
        .package(url: "https://github.com/Alamofire/Alamofire", from: "5.7.0"),
        .package(url: "https://github.com/onevcat/Kingfisher", from: "7.0.0")
    ]
)
```

**Target에서 SPM 의존성 추가 예시**

```swift
.target(
    name: "App",
    platform: .iOS,
    product: .app,
    bundleId: "io.tuist.app",
    infoPlist: .default,
    sources: "Sources/App/**",
    dependencies: [
        .external(name: "Alamofire"),
        .external(name: "Kingfisher")
    ]
)
```

#### Static vs Dynamic 링크

Tuist는 정적(Static) / 동적(Dynamic) 링크 프레임워크 관리도 지원합니다.

**예시 - 환경 변수 기반 링크 타입 설정**

```swift
import ProjectDescription

let isStatic = (ProcessInfo.processInfo.environment["STATIC_LINK"] == "true")

let frameworkType: Product = isStatic ? .staticFramework : .framework

let project = Project(
    name: "MyProject",
    targets: [
        .target(
            name: "Core",
            platform: .iOS,
            product: frameworkType,
            bundleId: "io.tuist.core",
            sources: "Sources/Core/**",
            dependencies: []
        )
    ]
)
```

**터미널에서**

```bash
STATIC_LINK=true tuist generate
```

이렇게하면 Core 모듈이 정적 프레임워크로 빌드됩니다.

#### 시스템 SDK 의존성

iOS에서 제공하는 기본 SDK도 의존성으로 추가할 수 있습니다.

```swift
.dependencies: [
    .sdk(name: "Contacts.framework", type: .framework),
    .sdk(name: "UserNotification.framework", type: .framework)
]
```

#### 바이너리 프레임워크 / XCFramework

```swift
.dependencies: [
    .framework(path: "Frameworks/MyFramework.framework"),
    .xcframework(path: "Frameworks/ThirdParty.xcframework")
]
```

#### XCTest 의존성

테스트 타겟에는 간단히 다음을 사용

```swift
.target(
    name: "AppTests",
    platform: .iOS,
    product: .unitTests,
    bundleId: "io.tuist.appTests",
    sources: "Tests/**",
    dependencies: [
        .xctest
    ]
)
```

#### 조건부(Conditional) 의존성

플랫폼별 다른 의존성을 걸 수 있습니다.

```swift
.dependencies: [
    .target(name: "Shared", condition: .when(platforms: [.iOS])),
    .sdk(name: "Metal.framework", type: .framework, condition: .when(platforms: [.macOS]))
]
```

#### Objective-C 라이브러리 주의사항

Objective-C 포함된 라이브러리 사용할 때는 Tuist가 플래그를 자동 추가하지 않기 때문에 수동으로 설정해야 합니다.

```swift
settings: .setting(
    base: [
        "OTHER_LDFLAGS": "-ObjC"
    ]
)
```
