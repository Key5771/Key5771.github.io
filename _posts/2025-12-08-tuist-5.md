## Tuist(Plugins + Hashing)

지난번에 이어서 Tuist를 살펴봅니다.

### Plugins

플러그인은 여러 프로젝트에서 Tuist 아티팩트(도구, 템플릿, 헬퍼 등)를 공유하고 재사용할 수 있게 해주는 기능입니다.

지원되는 아티팩트 종류는 다음과 같습니다.
- 여러 프로젝트에서 재사용되는 Project Description Helpers
- 여러 프로젝트에서 재사용되는 Templates
- 여러 프로젝트에서 재사용되는 Tasks
- 여러 프로젝트에서 재사용되는 Resource Accessor Templates

단 플러그인은 간단한 방식으로 Tuist 기능을 확장하도록 설계되었기 때문에 몇 가지 제약이 있습니다.

**제한사항**
- 플러그인은 다른 플러그인을 의존할 수 없습니다.
- 플러그인은 서드파티 Swift 패키지에 의존할 수 없습니다.
- 플러그인은 해당 플러그인을 사용하는 프로젝트의 Project Description Helpers를 참조할 수 없습니다.

#### Plugin 종류

1. Project Description Helper Plugin

Project Desciption Helper Plugin은 아래 구조로 구성됩니다.

```bash
MyPlugin/
 ├── Plugin.swift
 └── ProjectDescriptionHelpers/
       └── (여러 .swift 헬퍼 파일)
```

**Plugin.swift 예시**

```swift
import ProjectDescription

let plugin = Plugin(name: "MyPlugin")
```

2. Resource Accessor Templates Plugin

리소스 접근자(Resource Accessor) 템플릿을 공유하려는 경우 사용합니다.
디렉토리 구조는 아래와 같습니다.

```bash
MyPlugin/
 ├── Plugin.swift
 └── ResourceSynthesizers/
       ├── Strings.stencil
       ├── Assets.stencil
       ├── Plists.stencil
       ├── Fonts.stencil
       ├── CoreData.stencil
       ├── InterfaceBuilder.stencil
       ├── JSON.stencil
       ├── YAML.stencil
```

각 템플릿 파일은 리소스 타입의 CamelCase 형태여야 합니다.

| Resource 타입 | 템플릿 파일명 |
| :-- | :-- |
| Strings | Strings.stencil |
| Assets | Assets.stencil |
| Property List | Plists.stencil |
| Fonts | Fonts.stencil |
| Core Data | CoreData.stencil |
| Interface Builder | InterfaceBuilder.stencil |
| JSON | JSON.stencil |
| YAML | YAML.stencil |

프로젝트에서 사용할 때는 다음처럼 `plugin:` 옵션을 지정합니다.

```swift
let project = Project(
    resourceSynthesizers: [
        .strings(plugin: "MyPlugin")
    ]
)
```

3. Task Plugin(Deprecated)

>Task 플러그인은 더 이상 사용되지 않습니다.(Deprecated)
만약 자동화 도구가 필요하다면, 공식 블로그 글 참고가 권장됩니다.
>

Task는 $PATH에 노출되는 실행 파일이며, 이름이 `tuist-<task-name>` 형식을 따르면 tuist task-name으로 실행할 수 있었습니다.
하지만 유지보수 복잡도로 인해 해당 기능은 제거되었습니다.

**기존 Task 사용자를 위한 권장 대안**
- 계속 ProjectAutomation.xcframework 사용 가능
- ARM+x86_64 지원 fat binary를 직접 만들어 Github Releases 제공
- Mise 같은 설치 도구로 배포
- plugin repository를 사용해 사용자에게 설치 방법 제공

미래에는 ProjectAutomation과 XcodeGraph를 통합한 새로운 프레임워크를 제공할 계획이라고 합니다.
이를 통해 사용자가 자신만의 Tuist 같은 CLI를 만들 수 있게 하는 방향을 추구하고 있습니다.

#### Plugins 사용 방법

프로젝트에서 플러그인을 사용하려면 Tuist.swift에 플러그인을 선언해야 합니다.

**로컬 플러그인**

```swift
import ProjectDescription

let tuist = Tuist(
    project: .tuist(plugins: [
        .local(path: "/Plugins/MyPlugin")
    ])
)
```

**Git 플러그인 (여러 저장소에서 공유 가능)**

```swift
import ProjectDescription

let tuist = Tuist(
    project: .tuist(plugins: [
        .git(url: "https://url/to/plugin.git", tag: "1.0.0"),
        .git(url: "https://url/to/plugin.git", sha: "e345cba")
    ])
)
```

그 후 아래 명령을 실행하면 플러그인이 글로벌 캐시로 다운로드됩니다.

```bash
tuist install
```

#### Project Description Helpers Plugin 사용 시

프로젝트에서 해당 플러그인의 헬퍼 파일을 사용하려면 다음처럼 import 합니다.

```swift
import ProjectDescription
import MyTuistPlugin

let project = Project.app(name: "MyCoolApp", platform: .iOS)
```

### Hashing(해싱)

캐싱(cache)이나 선택적 테스트 실행(selective test execution)과 같은 기능을 사용하려면, 특정 타겟이 변경되었는지 여부를 판단할 수 있는 기준이 필요합니다.
Tuist는 의존성 그래프에 포함된 각 타겟에 대해 해시(hash)를 계산하여 변경 여부를 판단합니다.

타겟의 해시는 다음 요소들에 기반해 계산됩니다.

**타겟의 주요 속성**
- 이름
- 플랫폼(iOS/macOS 등)
- Product 타입(framework, app, library 등)
- 기타 설정 값들

**타겟의 파일들**
- 소스 코드
- 리소스
- 설정 파일 등

**타겟의 의존성 해시**
- 해당 타겟이 의존하는 다른 타겟들의 해시 값도 포함되어 재귀적으로 계산됩니다.

#### 캐시용 해시: 추가요소

캐싱을 위한 해시를 계산할 때는 위 항목 외에도 다음 요소를 추가로 반영합니다.

1. Swift 버전

Tuist는 `/usr/bin/xcrun swift --version` 명령의 경과를 읽어 Swift 버전을 포함하여 해시를 계산합니다.

이유는 다음과 같습니다.
- Swift 버전이 다르면 같은 코드라도 바이너리가 호환되지 않아 컴파일 오류가 발생할 수 있습니다.
- 따라서 바이너리가 생성된 Swift 버전과 프로젝트의 Swift 버전은 반드시 일치해야 합니다.

2. Build Configuration(빌드 구성)

`--configuration` 플래그는 다음을 보장하기 위해 도입되었습니다.
- Debug 빌드에서 생성된 캐시를 Release 빌드에서 사용하지 않도록
- 반대로 Release -> Debug 용도도 방지

하지만 Tuist는 아직 "프로젝트에서 사용하지 않는 configuration을 제거하는 기능"을 제공하지 않기 때문에, 이 부분은 향후 개선될 예정입니다.

### 해시 관련 문제 디버깅 방법

만약 서로 다른 환경(CI/로컬 등)에서 캐싱이 불안정하거나 같은 프로젝트인데도 Tuist가 서로 다른 해시를 계산한다면 아래 순서대로 문제를 점검하시는 것을 권장드립니다.

**1. 동일 환경에서 해시 일관성 확인**

```bash
tuist hash cache
# 또는
tuist hash selective-testing
```

- 명령을 실행해 해시 값을 복사합니다.
- 프로젝트 폴더 이름을 임의로 변경합니다.
- 같은 명령을 다시 실행합니다.

두 결과의 해시가 완전히 동일해야 정상이며, 다르다면 생성되는 프로젝트가 환경값에 의존하고 있을 가능성이 있습니다.

**2. 환경 의존성 확인**

해시가 다르다면 다음을 비교해보세요.

**2-1. 방식 A: 그래프 비교**

```bash
tuist graph --format json
```

두 환경에서 출력한 JSON을 비교합니다.

**2-2. 방법 B: Xcode 프로젝트 비교**

두 환경에서 생성된 project.pbxproj 파일을 Diffchecker 등으로 비교합니다.

**3. 환경값(특히 Swift 버전) 확인**

- Swift 버전은 Xcode 버전에 종속됩니다.
- 따라서 CI와 로컬의 Xcode 버전이 다르면 같은 해시를 얻을 수 없습니다.

따라서 반드시 동일한 Xcode + Swift 버전을 사용해야 합니다.
